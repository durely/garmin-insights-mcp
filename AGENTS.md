# AGENTS.md

MCP server (TypeScript, Node 24, stdio) for the Garmin Connect Personal API. It syncs a user's Garmin history into a local SQLite cache and serves tools that read from it.

## Where to look

- **Design decisions, roadmap, open questions:** `SPEC.local.md` (local only; may be missing in a fresh clone). Read it before adding a feature or changing architecture; update its phase table when a phase lands.
- **Garmin API behaviour** (range caps, empty-data shapes, auth, FIT contents, retention): `docs/garmin-api-notes.local.md` (local only). Read it before calling a new endpoint; add what you measure.
- **Runtime behaviour** (cache, sync, metrics formulas, Docker): [docs/how-it-works.md](docs/how-it-works.md).
- **Endpoint descriptions:** `src/garmin/generated/openapi.local.md` (local only; run `npm run openapi` if it's missing).

## Done means green

Tests live next to the code they cover (`foo.ts` + `foo.test.ts`); shared fakes and harnesses are in `src/testing/`. Both are left out of the build. A change is done when `npm run lint`, `npm run typecheck`, `npm test` and `npm run build` all pass; CI runs exactly these plus a Docker build. `npm run format` fixes formatting. Tests never touch the network. `npm run smoke` hits the real account: run it only when asked.

## Module boundaries

- `src/garmin/` is a standalone API client: no MCP or SQLite imports. It's meant to become its own package.
- `src/analysis/` holds pure functions, no I/O; tools fetch the data and pass it in.
- `src/mcp/tools/*.ts` each export a `register…Tools(server, ctx)` wired in `src/mcp/server.ts`. Tools read from the cache (`src/store/`). Garmin data enters the cache through `src/sync/` only: the background engine, plus `on-demand.ts` for days outside the synced window.
- `src/garmin/generated/openapi.ts` is generated by `npm run openapi`; regenerate it, never hand-edit it.

## Conventions and gotchas

- **stdout is the MCP channel.** Log through `src/log.ts` (stderr); a stray `console.log` corrupts the protocol.
- **Node runs the `.ts` sources directly:** import with the `.ts` extension and stick to erasable syntax (`erasableSyntaxOnly`): no enums, namespaces or parameter properties.
- **Dates are the user's local calendar dates** (`GARMIN_MCP_TIMEZONE`), built with the helpers in `src/garmin/dates.ts`. Garmin addresses wellness data by local date; UTC dates skip or duplicate a day around midnight.
- **Every range endpoint has a hard day cap** and Garmin answers an oversize range with a bare `400 {}`. Chunk by the caps in the API notes.
- **Schema changes:** migrations in `src/store/db.ts` are append-only; add a new one, leave released ones as they are.
- **Garmin attribution:** tools that return analysis (anything computed from Garmin data) render with `renderDerived` from `src/mcp/format.ts`, which adds the attribution Garmin's API brand guidelines require. Lead user-facing names with "durely" (always lowercase, also at the start of a sentence), with "Garmin" only describing what it works with.
- **Adding or renaming a tool:** update the tool list in `src/mcp/server.test.ts` and the tools table in `README.md`. Set `annotations` the way the existing tools do: read-only tools say `readOnlyHint: true`.
- **FIT parsing uses `fit-file-parser` (MIT)**, behind the `FitParser` interface. Don't add `@garmin/fitsdk`: its license forbids redistribution, which the Docker image would do.
- `spike/` is local, throwaway exploration (gitignored).

## Privacy: the repo is public

- **Test data is invented.** Use `src/testing/fake-garmin.ts` and the synthetic FIT builder in `src/testing/fit-fixture.ts`; keep real API responses, FIT files and exports out of the repo (exploration against a real account lives in the gitignored `spike/`).
- **Docs describe the API, not the account.** In the API notes and SPEC, write findings in general terms: no activity IDs, activity dates, race details, coordinates or personal metrics.
- **Tool output omits identity and location.** Owner name, display name, profile images and account ID are stripped before caching (`OWNER_FIELDS` in `src/store/store.ts`); GPS appears only when the caller explicitly asks for it. Keep new tools to the same rule.
- **Garmin's own text stays local.** Put it in a `*.local.md` file (gitignored), like the OpenAPI descriptions.

## Writing docs

`README.md` is for users: setup and what to ask. Technical detail goes in `docs/how-it-works.md`. Write plainly, with short sentences and concrete numbers.
